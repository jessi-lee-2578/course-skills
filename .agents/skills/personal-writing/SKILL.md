# 中文写作

以作者最新手改稿为底稿。需要摸清写法时，优先看本人原话、明确说过为什么要改的地方，以及已经认可的版本。若同时有教师要求、旧初稿和最终稿，从教师要求提取交付范围，从对照稿提取写法。AI 生成过的旧稿只作为对照；作者身份无法确认的文字按协作稿处理。当前任务限定改动范围时，只处理指定部分。

## 与作者一起推进

需要从题目或零散材料一起写成文时，先打开 [协作与逻辑检查](references/coauthoring.md)。要求贴近本人文风时，先打开 [样稿读法与试写案例](references/writing-examples.md) 并对照本人样稿。更新长期要求时执行 [课程资料与偏好记录](references/course-context.md) 的写回步骤。

1. 先读当前材料，简短复述你理解的主张及最能支撑它的材料。作者已经给了明确观点或事实时直接用。若缺少作者自己的想法，先问一个具体的开放问题，让作者用自己的话回答。已经知道作者想表达什么，但结构或侧重点仍有取舍时，再给少量选项，说明各选项会改变什么。
2. 对新写的长文，先把主线和对应材料列成简短提纲，再试写最容易偏离作者原意的一段。邀请作者用自己的话改中心判断或补一处细节。修改得到反馈后带回全文。只改几句、已有充分材料或作者已要求直接成稿时，按任务规模推进。
3. 作者尚未回答时，先做能独立完成的阅读、引文定位和结构梳理。把需要本人决定的内容留在提纲的具体位置，可先写有依据的部分。详见 [协作与逻辑检查](references/coauthoring.md)。

## 学习这位作者的文风

需要贴近本人写法时，优先用同体裁的本人稿、明确认可的段落或同段改稿对。读出开头怎么落到具体事、判断放在什么位置、一段如何展开，以及常用的语气和句子节奏。记录两三条能在试写中看出来的规律。作者明确说过的偏好直接用，从单篇样稿推出来的规则先通过一小段试写校准。只把样稿当作表达方式的证据，稿里的经历、观点和引文须有本次材料支持才能沿用。

如果手头没有样稿，只在文风会明显影响交付时请作者贴一小段。先按自然的中文起草需要的部分，并根据作者反馈调整。仓库里的示例是一位作者的写法，其他使用者可用自己的样稿替换。具体操作和示范见 [样稿读法与试写案例](references/writing-examples.md)。

跨次任务开写前，读取用户指定的写作记录或固定项目里的 `.course-context/personal-writing.md`。作者确认将某条规则长期沿用时，实际更新 Markdown 并报告其路径。参见 [课程资料与偏好记录](references/course-context.md)。

## 行文

写正文、讲稿或幻灯片文案时，按 [成稿用语检查](references/wording-check.md) 做一次用词与句式复查。作者明确要求避开的表达记入个人课程记录，自写内容遵循，引用与原题准确保留。

- 开头尽早交代正在讨论的对象、作者遇到的事或作者直接作出的判断。从真实场景切入时，给读者看得懂的动作和细节，再写作者为什么在意。
- 用平常的陈述句推进。去掉为营造悬念而设的问句、排比口号、假对话和反复的小标题。真实问题、原书标题和老师给的思考题按需要保留。
- 让作者的意见用本人愿意承担的力度表达。把惯常出现的「并不等于」「不能据此认为」替换成具体判断和理由。涉及关键条件时在相关句里交代一次，明确它实际影响的是哪一项结论。
- 同一意思说透一次。相关的动作、观察和判断可以接成一句或一段，以自然的停顿组织长短句。删掉重复段末总结和只负责过渡的空话。
- 作者已经写清的经历和观察优先保留，编辑错字和接缝时保住原意。补写经历、观点和原文引语需要材料。缺什么就标出来，避免把猜测写成第一人称经历。

交稿前用一句话复述每段在做什么，逐段检查这个判断从哪条材料来、为何顺势来到下一段。缺中间一步就补出关系，位置不对就调序。重要稿件可让未看过聊天的读者用成稿复述主张和依据。需要更完整的独立试读流程时，参阅 [Doc Co-Authoring 的 Reader Testing](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md#stage-3-reader-testing)。
