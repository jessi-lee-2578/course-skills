# 课堂 PPT

开始前读取用户指定的记录或项目下的 .course-context/classroom-presentation.md。长期设置更新到记录文件，成品只使用本次展示需要的内容。

先读本次材料，弄清听众懂什么、你要让他们听懂什么、能讲多久。若需要沿用模板或局部调整，打开用户最新手改版判断页间关系，保留已经确认的内容。

讲述目标有歧义时，先问用户最想让听众听懂什么。用户已经给了顺序、重点或讲稿时就用这些信息。重点已知、材料能支持不同的叙事顺序时，再说明两条顺序各需要哪些证据、各花多少时间。新演示可以先拿最重要的两三页试讲，听完反馈再扩到全套。

按本次任务选择步骤。新做整套走下方的编排与制作。局部修改从当前 PPTX 出发，定位指定页和受影响的前后衔接。只写讲稿直接按文末的讲稿检查处理。

涉及屏幕文案或讲稿，动笔前打开 [课堂 PPT 文案与转场](references/slide-copy.md)，交付前执行 [通用用语要求](../personal-writing/references/wording-check.md)。需要制作或修改 PPTX 时，同时执行文末的 PPT Master 调用步骤。

1. 先写一遍口头能讲通的顺序。每页只列一个主要任务、可展示的证据，以及它怎样承接前页。例如先交代为什么同一个请求会落到另一台推理服务器，再讲第二台存了哪些缓存，最后比较取缓存和重算的代价。第一次出现的术语就地用一小句解释。
2. 正式制作前先确认外观。用户已经给了模板或用自己的话描述了具体风格，就记录这项选择；尚无方向时，给两到三个与内容相符的模板或样式，展示相关页面与来源，说明推荐哪一个、为什么。用户可以选择模板，也可以直接描述想要的风格。确定前先做资料梳理、逐页提纲和文案试写，正式排版与生成从选定后开始。
3. 模板主要提供字体、色彩和视觉体系。逐页根据内容选机制图、代码、证据图或对比版式。按 [课堂 PPT 文案与转场](references/slide-copy.md) 写标题、屏幕字和口播，先把几页的实际文案读顺。完整文案交给制作流程前，查一遍 [通用用语要求](../personal-writing/references/wording-check.md)。
4. 逐页查因果和过渡，再检查字体适合投影、文字是否溢出及动画触发是否正确。原理动画每一步对应一个要讲的动作。用户手改过的页以最新稿为准，避免用旧版重新生成时覆盖。

初稿检查可以只看标题和缩略图。如果仅看标题就说不出为什么要翻到下一页，先修讲述顺序。逐页排版时用最终 PPTX 和放映效果核对承诺的版式和动画。若无放映工具，说明实际检查到了哪一步。

配讲稿时读取实际要放映的版本，逐页核对页码、图表、代码和点击动作。在提到一个变量或做对比之前，让听众先知道它代表什么、两组比较条件是什么。按预计语速连贯读一遍，核对转场和总时长。数据展示已有相关性或同时变化时，用口播交代观测，再根据证据决定能否讲成因。

## 调用外部 Skill

- 要制作或修改 PPTX，先加载 [PPT Master](https://github.com/hugohe3/ppt-master/blob/main/skills/ppt-master/SKILL.md) 的对应流程。把已选模板或风格描述、逐页标题与屏幕文案、样稿、需保留页和点击次序作为制作输入。制作中以已确认文字为准，交付前对照成品中的实际文字、指定页面和顺序。缺少该 Skill 时，先查阅能访问的上游步骤，再使用已有 PPT 能力。只有文本工具时交付页序和文案。
- 需要原创新图或图片编辑时，PPT Master 项目读取 [PPT Master 配图流程](https://github.com/hugohe3/ppt-master/blob/main/skills/ppt-master/references/image-generator.md)。独立配图且当前有对应的图像能力时，加载 [Image Generation](https://github.com/openai/skills/blob/main/skills/.system/imagegen/SKILL.md) 或用户指定的创作 Skill。缺少图像工具时，把构图、图中信息和用途写成制作说明。
