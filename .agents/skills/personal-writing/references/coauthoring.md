# 如何和作者一起创作

## 协作记录与准入条件

新写、实质重写或正式制作前，在本次工作区的私有目录维护 `brief.md`。可放在 `.course-context/<本次任务>/brief.md`，与提交物隔离；同时处理多题时逐题记录。宿主无法写文件时，在对话中发出同等内容。写明：

- 题目、交付物、用户确认过的评阅对象和当次要求。
- 用户自己的切入点、观察或想保留的原句，并注明来自哪份材料。
- Agent 找到的证据和候选角度，标出哪些还需用户确认。
- 当前阶段、缺项、已确认的提纲或试写，以及是否有用户明确授权跳过的环节。

记录存在只说明材料已整理。作者观点、实验现象及必要的阶段反馈要有用户消息或用户资料作为依据。评阅对象尚未明确时直接问；本人观点缺失时绑定一条材料提问。收到答复前停在阅读、引文核验、数据转录或提纲阶段。正文、结果、第一人称判断和可提交文件都须等对应 Skill 的前置条件满足。用户催促、只说「直接给我成品」或没有回复时，维持当前阶段。

## 第一轮先把问题问具体

先看用户已经给出的材料和对话。说清你目前读到的重点和一个真正会改变内容的缺口。每轮只问一两件最有价值的事，问题绑定到一段话、一张图或一个决定。用户可以给几句口语、图片或关键字，Agent 负责整理和核对。

| 任务和现有材料 | 可以这样接着问 |
| --- | --- |
| 读书报告只有书名和作业要求 | 「你读到哪一段时最想赞成或反驳？记不清页码也行，给我一个关键词，我先帮你定位。」 |
| 实验记录表容易读，报告缺少误差分析 | 「这组电压和其他组走势不一样。你当时看到的是仪表零位变化，还是温度显示稳住以后电压还在变？有现场照片或记得大致顺序就够。」 |
| PPT 有很多材料，未定讲述重点 | 「你这段只有三分钟。听众听完应该会解释算法为什么成立，还是能讲清哪次实测显示它更快？两点都有材料，优先讲哪一个会决定前几页怎么排。」 |
| 作者已有观点、细节和手改稿 | 「我理解你最在意的是现场没有留够分析时间，我会保留你写的那段，只补读者需要的验收背景。」直接处理清楚的部分。若两种理解会得出不同文章，再就那一处问。 |

问题里提到的现象必须来自当前材料。如果材料尚未读到异常，就问「有没有哪次读数让你停下来重测」，让作者用自己的观察回答。涉及本人立场的选项只是帮助表达，给作者留出补充和纠正的空间。

## 在成稿前过一遍逻辑

- **文章。** 依次读每段的主要判断和证据。如果去掉「因此」「然而」就找不到两段之间的关系，回去补必要事实、解释或调顺序。依据只支持一个局部判断时，把判断落到那个范围。
- **实验与项目。** 从操作找到现象，从现象找到记录的位置，再写解释和结论。比如电压读数漂移要交代发生在哪步、怎么修正、影响哪张图或哪项结果。波形中某个值突然改变，要核对是同一表项被更新，还是观察窗口切换了地址。表现更快和某项操作变少可以分别报告，归因需要对应的额外证据。
- **PPT 和讲稿。** 先只看标题把故事说一遍，再按放映顺序讲一遍。每次翻页前应有一个具体理由。口播提到的代码、图例或数据此时应该已经可见。时间紧先缩减支线，保留理解下一页所需的前提。

最后把仍需作者决定的地方精确到段、表格或页，让反馈能直接改进成品。
