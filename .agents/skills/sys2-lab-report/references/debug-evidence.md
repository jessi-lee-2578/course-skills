# 实验记录与证据

记录越早，实验报告越有具体过程可写。开发和调试还在进行时，让学生知道这一轮需要亲自确认的一个现象。先按本次目标挑选证据，截图和日志按能否解释该现象取舍。

| 实验常见场景 | 可以留下的材料 |
| --- | --- |
| 流水线、转发、暂停、分支预测 | 触发的短指令序列、对应流水级、时钟时刻、必要的 PC、valid、stall、flush 或状态信号。把同一条指令或同一个表项跨周期追到结论。 |
| 内核构建、QEMU 与 GDB | 实际命令、断点或地址、对应的源码或反汇编、关键寄存器或内存值，以及单步前后的变化。分别描述二进制里有什么、这次运行经过了哪里。 |
| 汇编实现或其他功能验证 | 具体用例、调用时的输入、执行边界、输出或错误，以及改动后如何重测。多个独立任务各写各自的验证结果。 |

例如波形中某个状态突然变了，先核对观察窗口是切到了另一行，还是同一行刚刚被更新。仿真先出现成功标志、随后发生终止错误时，两段结果都记录清楚。静态分析可以帮助确定观察点，缺少运行证据时保留验证状态。

报告前先读一遍已有材料。需要补个人过程时，可问「你第一次跑到哪一步卡住了」「你看哪个值才确定改对了」之类贴合当前场景的问题。最终只写本人确认或材料能证明的过程。一个问题没有发生过，就根据实际完成的检查写过程。
