# 东方文明史

先读本次作业要求、原题、课件和用户已经给的想法。在可访问的材料中找最新版手改稿、已确认答案、已交范本和前一次改动记录。原题用来定问题，手改稿用来定正文与文风，已交范本用来定结构。按当前任务选下面的流程，交付前查证本次实际采用的资料。

跨周写作先读用户指定的课程记录或课程项目里的 `.course-context/eastern-civilization.md`。本人确认会长期使用的措辞、样稿和范本入口，当轮实际更新 Markdown。把还需校准的文风观察单列。参见 [课程资料与偏好记录](../personal-writing/references/course-context.md)。

## 每周讨论题与分周作业

先打开 [分周作业、文风与改稿](references/weekly-writing.md)。写完整稿时同时打开成文模板与通用用语要求，交稿前执行各自的检查。 [成文模板](references/answer-template.md) · [通用用语要求](../personal-writing/references/wording-check.md)

1. 用户熟悉题目时，先听他已经想到的联系；陌生时，先给理解原题所必需的背景和少量资料，再问一个能延展其想法的问题。有观点就接着补依据，避免把同一问题换个说法反复问。
2. 把观点、例子和推理顺序列成简短逻辑链。每个主要理由找具体的人物、制度、事件、实物或文本。补足案例与结论之间的解释，发散后回到原题。历史资料中的判断标明出处，第一人称只写用户真正表达过或认可的想法。
3. 用户要求「成文」「写完整回答」或提交版时，打开 [成文模板](references/answer-template.md) 并按其栏目组织。默认**每题「回答」正文约 800–2000 字**，原题、逻辑链、AI 辅助学习说明和参考资料单独计算。教师或用户当次另有字数要求时按当次要求。
4. 正文通常展开两到三个有实质区别的例子或证据点。写清各自支持哪一步、怎样共同回答原题。比较题按同一维度比较，单案例题可展开同一案例中不同的材料或环节。交稿前逐题核对正文长度、论证与例子，并检查 **回答、AI 辅助学习说明、参考文献与链接** 三项是否齐全。材料不足时先补查，再把真正缺少的作者观点或证据具体标明。按 [分周作业、文风与改稿](references/weekly-writing.md) 保留作者的判断和写法。

## 史实和链接由 Agent 先核实

用到史实、图源或引文时先打开 [来源核验流程](references/source-checking.md)。正文、海报或展示使用的链接，由 Agent 打开逐条检查。分别记录链接是否抵达正确的来源、实际读到哪一层、那段内容支持哪条主张。给用户能直接点开的来源和定位；用另一款 AI 复核由用户自行选择。

## 展览海报

接到海报任务先打开 [海报样式、出图与修改](references/poster-workflow.md)。根据本次题目确认文明、展出地、受众和用途。先给两到三个具体样式，说明主视觉、排版和取舍，请用户明确选择并说说想法。**用户明确选择前停在提案阶段，暂缓正式创作。** 用户已经明确指定样式并给过想法的，记录其选择后继续；反馈只有「都行」时，给出首选和理由，请他确认。选定后必须走对应的创作流程，并按流程核对、返修。

## 个人 AI 使用展示

只有作业明确要求或用户提出时才附 AI 使用说明。根据真实记录写用过的模型、具体用途、Agent 怎样核对来源、自己作出的选择与改动。挑一条核验后确实有变化的表达，或一组海报修改前后图，说明为什么改。以个人提交为范围，按本次作业或范本提供文件。
