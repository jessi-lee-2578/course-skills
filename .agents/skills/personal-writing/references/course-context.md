# 把课程约定写进可复用的 Markdown

有明确的长期偏好、需要重复打开的模板或跨次作业的确认状态时，实际创建或更新记录。只说「记住了」无法让后续任务找到这些资料。

## 从哪里读

1. 先找用户明确指定的记录文件或私人资料目录。已有固定记录就继续用它。否则，从本次课程项目根目录查找 `.course-context/<skill-name>.md`。通用写作没有独立课程时用 `.course-context/personal-writing.md`。
2. 开始撰写前读取记录，按其中的路径找到模板、课表或样稿，打开核对版次和适用范围。当前明确要求优先。旧记录里的周次、实验参数、单次反馈仅供定位。引用文件移动时，先在当前课程材料里按文件名查找；查不到再说明哪个文件缺失，继续能做的内容。
3. 新对话如果沿用同一个课程项目，走同一条查找路径。换了项目或电脑时，需要用户点名原项目、提供记录目录或上传记录文件。对话中的历史信息可以帮忙定位文件。用户可直接改记录，也可以从 [设置样例](../../../../course-context.example.md) 起步。

## 写什么，以及什么时候更新

- 首次需要记录且文件尚未存在时，在指定位置或课程工作区的 `.course-context/` 创建 Markdown。记录「已确认的长期规则」和「资料入口」两节，写清适用范围、模板或样稿文件名及路径。资料更新时补适用学期或版本。资料入口优先使用相对于课程项目的路径，跨目录的私有文件可以写绝对路径。
- 用户明确说以后都这样、反复纠正了同一问题并确认要沿用，或者提交了新的固定模板时，当轮更新对应条目并读回核对。对本人样稿学到但还没由本人确认的写法，单列为「待确认」，得到反馈再移入长期规则。一次性要求跟随本次作业稿；符合其范围的近期进度可以单独注明日期。
- 已有规则变更时更新原条目，保留仍适用的内容。把首次创建或本次更新的文件路径和主要变化简短告诉用户。记录存在本地课程项目或用户指定的私人位置。公开仓库只放示例和说明，真实样稿、个人标识和私有路径留在使用者自己的课程工作区。

例子：大学物理实验的记录可写「开写前分别查找预习/正式模板；从实际打开的模板沿用章节与版式；再按本次课表和讲义填写」，另列两个模板的具体路径、课表学期和文件路径。下次先打开相应 Word 模板才能算完成这一步。

各课程的正式提交物只写课程要求的内容。工作日志、调研对话、用户设置和内部核对记录留在私人工作区。课程明确要求交付的 AI 使用说明或实验过程记录按当次要求组织成独立的正文或附录。
