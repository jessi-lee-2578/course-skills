# 课堂 PPT 文案与转场

## 按听众能理解的顺序写

开头交代一个具体场景或任务。讲机制时持续用同一组对象和名字，让读者追得上对象何时出现、状态哪里变了。首次出现专业词时，先说明它在当前图里做什么。成为后文前提的背景先讲，补充性定义放图注或口播。

早期 KV Cache 课件在第 7 页用「Mooncake：围绕 KV Cache 组织推理」，直接转向新系统。后来的课件增加了「分页之后，缓存仍留在 1 号服务器」，接着才讲第二台服务器怎么拿到缓存。这句承接话补上了一个缺失的事实：前面的分页机制讲完后，第二台服务器还是需要找到原有缓存。

## 屏幕文字与口播

- 主要页标题写一句能说出口的陈述，例如「昇腾服务器从共享池读回 KV」。比较页可以直接写比较对象，例如「读取缓存和重新计算的耗时对比」。标题列表可单独从头读一遍，检查相邻页的前提和动作。
- 真正要让听众带入情境的开场可以用一句问句，例如同一份资料被问两遍时要不要重算。中间的机制页和结论页以陈述为主。成稿检查是否多页连续使用「如何」「为什么」「到底」「会留下啥」等问句标题，改写成对象、动作和结果。
- 图旁只留读图必须的标签、单位和结论。完整的口头解释按需另写讲稿。讲稿照着实际放映顺序走，每次点击出现的图、代码或数据要和这一句口播对应。
- 数据标题写实际比较范围。一组运行记录只承载它确实测到的结果，需要解释性能原因时另给相应证据。若课件展示的是某类设备的数据，标题或图注把设备和场景写清楚。
- 如果封底是例子的最后一步，优先用图或一句话把故事讲完。可以参考 KV Cache 后来的「两次提问共用一份缓存」，把案例中的两次请求和两台服务器重新连起来。来源按课程要求放到观众能查到的位置。

交付前用 [通用用语检查](../../personal-writing/references/wording-check.md) 查屏幕文字和口播。把最新版保留页单独记下来。用户只要求改一句或几页时，从本人当前稿改，随后逐页查看相邻转场和改动区域。
